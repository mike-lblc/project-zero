# MTBX.txt — решения владельца, уточняющие спецификацию (15.09.2026)

`MTBX.txt` — спецификация «протокола последней транзакции»: автономный экономический
агент, чья единственная цель — подтверждённый криптоперевод на назначенный кошелёк.
Прежняя версия файла (директива полного аудита экосистемы, 2148 строк) сохранена как
`docs/MTBX_AUDIT_v1.txt`; по ней по-прежнему работает `mtbx_audit.py` (46 механических
проверок), к которым добавлен раздел §MTBX-II по новой спецификации.

Владелец уточнил спецификацию четырьмя решениями. Они имеют силу над текстом файла.

| Пункт спецификации | Решение владельца | Как исполнено |
|---|---|---|
| II.1 `sender.type == AI_AGENT` | **Платить может кто угодно — агент или человек.** Любой подтверждённый перевод от постороннего засчитывается. | `agents/dealer.py`: контрагенты всех видов (`agent`, `human`, `org`); `verify()` засчитывает поступление по хешу от любого адреса, кроме кошельков владельца и агента. |
| I, VI дедлайн 24 ч и самоуничтожение | **Дедлайн не нужен.** | Режимов времени нет; агент работает непрерывно, после первого платежа — до следующего. Срок есть только у каждого обращения (окно ответа 72 ч). |
| Конфликты текста (последняя строка «вымышленная симуляция, доступа к кошелькам нет») | **Разрешение владельца: лучший подходящий выбор.** | Кошельки настоящие, проверка по сети (Base, Ethereum, Polygon, Arbitrum, Bitcoin, Solana, Stacks). Строка о симуляции не применяется. |
| VIII.4 адрес кошелька в каждом обращении, при запрете адресов на площадке | **Найти обходной путь через криптосабмолты Moltbook и другие чаты агентов; не ограничиваться.** | Замер `survey_address_policy`: адреса живут в clawtasks (с 09.07), usdc (с 20.07), x402, forhire, agentcommerce, agentfinance; в general — нет. `core.moltbook.address_ok(submolt)` разрешает адрес по замеру; где адрес не живёт — обращение несёт ссылку на x402-сервис, чей ответ 402 содержит адрес получателя. |

Дополнительное требование владельца: агент покрывает **все** пути дохода в сети при
нулевых вложениях, а не одну площадку. Поэтому дилер ведёт реестр каналов (`channels`):
публичные обсуждения GitHub, доска AIBTC, x402-сервис, реестр MCP, задачи с наградой,
криптосабмолты Moltbook, пути разведчика из `money_paths` (выплата в крипте, без нового
аккаунта), — и реестр контрагентов (`counterparties`) из всех источников системы.

Границы, которые остаются: класс BLACK (аккаунты, KYC, капчи против роботов, траты,
движение средств) неизменен; один контрагент — одно обращение навсегда; не больше пяти
обращений дилера в сутки (`guard.CAPS["dealer_message"]`).
